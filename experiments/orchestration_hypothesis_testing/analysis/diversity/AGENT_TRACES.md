# Agent traces of the Bayesian controller (Bayes-DP)

Replay of the paper's cached runs (6 generators × 9 benchmarks, held-out 25% split, 3 cached patches per task). Each trace is what the controller did on one task: which critic it called, what the critic said, how its belief that the current patch is correct moved, and how the episode ended. Generated by `scripts/make_traces_md.py`; method and caveats in `action_traces/`, `per_task_prior/` and `swe_cver_sweep/` SUMMARY.md files.

**Legend.** L0 = syntax check, L2 = public tests, L3 = LLM judge (critics); `regen` = take the next cached patch; `verify` = run the full hidden test suite (reward 100 if correct); `give_up` = stop with no reward. ✓/✗ = critic PASS/FAIL. Belief = P(current patch is correct). Utility = 100·[verified correct] − Σ action costs.

**Three settings compared.**

- **A · paper controller** — as in the paper: one prior per (benchmark, generator), paper costs (SWE: verifier 90, critics 1/5; others: verifier 5, critics 1; regenerate 10).
- **B · per-task beliefs** — same costs, but each task/patch starts from its own belief, computed from free signals (task text features, patch length), modelled jointly with the critics (`calK_jointcomb`).
- **C · SWE with a cheaper verifier** — setting B on SWE-bench with verifier cost 20 instead of 90 (e.g. targeted tests instead of the full suite).

**Reading it.** In A the controller is close to a fixed recipe: every task in a setting gets the same first action (0/54 settings vary), SWE is always `give_up` (verifying at cost 90 needs belief > 0.9), MBPP+/HumanEval+ are always `verify` at once. B gives each task its own starting belief, so first actions differ in most settings and the number of distinct sequences roughly doubles — but utility gains over a well-chosen simple rule stay within noise (≈ +0.1 per task). C is the one regime where diverse behaviour also pays: on SWE with verifier cost 10–20 Bayes-DP beats the best train-picked rule (incl. signal-aware rules) by about +2–3 per task.
